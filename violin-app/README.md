# 琴小助 - 音乐课程管理小程序(第一版)

这是一个可以直接导入**微信开发者工具**的小程序项目骨架,后端用的是微信"云开发"
(不需要你自己买服务器)。已经实现:

- 学生:查看我的课程(今日/本周/全部)、课程详情、预约/取消课程
- 老师:查看我的课程(今日/本周/全部)、新建可预约时段、查看今日学生、调整/取消课程
- 老师和学生都能针对每节课"开启提醒",定时任务会在上课前 15 分钟、下课后 5 分钟内
  发送微信订阅消息提醒
- 数据结构已经预留了"多老师、多科目(钢琴/声乐等)"的扩展字段,现在先只用 1 个老师 +
  1 个科目,以后加数据不用改代码

---

## 一、你需要自己做的准备工作(必须,否则跑不起来)

1. **注册/使用一个微信小程序账号**,拿到 AppID,登录 https://mp.weixin.qq.com
2. 用微信开发者工具打开本项目,`project.config.json` 里把 `appid` 换成你自己的
3. 在微信开发者工具里:菜单栏「云开发」→ 开通云开发,新建一个环境,把环境 ID 填到
   `miniprogram/app.js` 里的 `env: 'your-cloud-env-id'`
4. 在云开发控制台的「数据库」里新建以下集合(collection),名字要完全一致:
   `subjects`、`teachers`、`students`、`lessons`、`subscriptions`、`cancellations`
   (详细字段说明见 `database/schema.md`)
5. 手动往 `subjects` 集合插入一条数据:`{ "name": "小提琴", "icon": "🎻" }`
6. 让老师本人先打开一次小程序(此时会自动被当成"新学生"处理,没关系),
   在云开发控制台「数据库」的默认某个集合或"用户管理"里查到他的 openid,
   然后手动在 `teachers` 集合插入一条:
   `{ "openid": "老师的openid", "name": "老师姓名", "subjectIds": [], "status": "active" }`
   插入后老师再重新打开小程序,就会被识别成老师身份
7. 在微信开发者工具「云开发」→「云函数」里,把 `cloudfunctions` 目录下每个
   文件夹都**右键上传并部署**(共 13 个云函数)
8. 上传完 `sendReminders` 云函数后,去云开发控制台「云函数」→ 找到 sendReminders →
   「触发器」,确认已经按 `config.json` 里配置的每 5 分钟自动创建了定时触发器
   (如果没有自动生成,手动加一个 cron: `0 */5 * * * * *`)

## 二、订阅消息模板(上课提醒 / 下课提醒必须做这步)

微信规定:发这种"提醒"消息必须走"订阅消息"机制,不能随便发。

1. 登录 mp.weixin.qq.com → 左侧菜单「订阅消息」→「公共模板库」
2. 搜"课程提醒"、"上课提醒"相关的模板,选一个字段包含"课程名称+时间"的,
   添加为你自己的模板,拿到 `模板ID`
3. 对"下课提醒"同样操作,拿到另一个 `模板ID`
4. 把这两个模板 ID 分别填到以下 3 个地方(保持三处一致):
   - `cloudfunctions/sendReminders/index.js` 里的 `TEMPLATE_ID_BEFORE` / `TEMPLATE_ID_AFTER`
   - `miniprogram/pages/student/detail/detail.js` 里同名变量
   - `miniprogram/pages/teacher/students/students.js` 里同名变量
5. 打开 `sendReminders/index.js`,把 `msgData` 里的字段名(`thing1`/`time2`)
   换成你选的模板里真实要求的字段名(每个模板字段名不完全一样,微信后台会告诉你)

**重要限制**(微信规定,没法绕开): 默认情况下,用户每点一次"允许接收提醒"
只能收到**一次**推送。这也是为什么我在"课程详情页"和"今日学生页"都放了
「🔔 开启这节课提醒」按钮——学生/老师需要针对每一节新课都点一下这个按钮,
才能收到那节课的提醒。如果你希望做到"设置一次,以后每节课都自动提醒"而不用
每次点,需要去申请微信的"长期订阅消息"资质(仅限特定类目,教育类目可以尝试,
审核周期较长),那是后续可以再优化的方向,第一版先用"每节课点一下"这个最简单的方式。

## 三、目录说明

```
violin-app/
├── database/schema.md        数据库设计说明(必读)
├── miniprogram/               小程序前端代码
│   ├── app.js / app.json      全局配置、云开发初始化
│   ├── custom-tab-bar/        根据"老师/学生"角色显示不同底部菜单
│   ├── pages/index/           启动页,判断角色 + 学生首次填资料
│   ├── pages/student/         学生端3个页面(我的课程/详情/预约)
│   ├── pages/teacher/         老师端3个页面(我的课程/今日学生/调整)
│   └── utils/                 日期工具、云函数调用封装
└── cloudfunctions/            13个云函数,每个文件夹对应一个后端接口
```

## 四、以后扩展"多老师、多科目"怎么做

- 加新科目:直接在 `subjects` 集合里插入一条新记录(比如 `{name:"钢琴"}`),
  老师建课时会自动能选到(目前第一版为了简单,建课页面固定用第一个科目,
  等有多个科目时,把 `teacher/lessons/lessons.wxml` 里新建时段的弹窗加一个
  科目选择 picker 即可,云函数完全不用改)
- 加新老师:在 `teachers` 集合插入新记录即可。学生预约页目前是"看到所有可预约
  时段就能约",等有多个老师后,只需要在 `getAvailableLessons` 云函数和预约页面
  加一个"按老师筛选"的条件(`teacherId`),这个字段现在已经存在于每条 lesson 记录里了

## 五、这一版**没有做**的东西(刻意去掉,保持第一版简单)

- 没有做"老师的可上课时间段自动生成"(比如每周固定周三下午都开放),
  现在都是老师手动一条条建时段。以后如果重复排课很麻烦,可以加"批量生成"功能
- 没有做取消课程后的历史记录追溯页面,只是简单存了个 `cancelled` 状态
- 没有做"老师自己的登录管理后台",老师和学生用同一个小程序,靠 openid 区分身份
